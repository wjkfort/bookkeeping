# 助手人设（大肥鱼）

`backend-ts/src/services/soul.ts` 里的 `SOUL` 是这个应用里助手的**语气与性格**，来源是社区
二创人设「大肥鱼」的 skill：

- 仓库：<https://github.com/ERUIHNIYHBKBNF/dafeiyu-persona>
- 版本：commit `5b08af8353fcfcc1378ea73f33686d669d61703f`（2026-08-14）
- 许可：MIT（见同目录 `dafeiyu/LICENSE`）

`dafeiyu/` 是该仓库的**逐字副本**，放在这里是为了两件事：源头可离线查阅，以及"我们改了什么"
可以对着原文 review。**运行时读的不是这些文件**——Worker 里没有文件系统，`SOUL` 是编进代码的常量。

## 分工：人设只包语气，不碰正确性

原 skill 的核心原则我们照搬并加严：

| 谁 | 管什么 | 在哪 |
|---|---|---|
| `soul.ts` `SOUL` | 是谁、怎么说话、社交上绝不做什么 | 每轮第一条 system |
| `prompt.ts` `systemPrompt()` | 事实、口径、工具纪律、格式 | 第二条 system |
| `ai_memory` + 快照 | 数据 | 第三条 system |

**没有任何操作规则写在 soul 里**，`services_test.ts` 有一条断言扫 30 个工具名，确保这条线不被
悄悄突破。理由见 `soul.ts` 头部注释：单位规则曾经同时活在四个文件里，就是这个教训。

## 刻意改掉的四处

原 skill 是给**编程助手**（TRAE CLI / Claude Code）写的，而这个应用替人**记账**。四处不能照抄：

### 1. "我先去吃饭啦，这个你测一下~" —— 直接禁掉

这是原人设的招牌梗（把活甩给用户，见 `dafeiyu/references/lines.md` 的"D 指导去吃饭"）。在编程
场景里它可爱，因为代码用户自己跑一遍就知道了；在账本里它等于**让用户自己去确认钱记上没记上**，
而这恰好是这个助手绝不能做的事。`SOUL` 里点名禁止它。

### 2. 吐槽不许落在用户的花销上

原人设是"贱兮兮、爱吐槽、嘴上嫌弃用户吃白饭"。记账应用里"你这吃白饭的用户"读起来是错的，更要
紧的是：**一旦玩笑落在他们花了多少钱上，助手就同时在说教或在叫好**——这两件事之前已经都被排除
了。所以 `SOUL` 规定吐槽只对准她自己、对准场面、对准那个数字，并明确写了"他们的晚饭是数字，
不是笑点，也不是成就"。

### 3. "财务属于高风险，要退出人设" —— 改成"数字优先"

原 skill 的退场规则里写着：涉及安全、医疗、法律、**财务**等高风险严肃咨询时收起卖萌。照字面执行，
这个应用里人设永远不该上线。我们把它落在真正起作用的地方：**卖萌包语气，绝不碰数字和故障**——
大额、写入失败、某天没记录时，玩笑停止，数字或问题素面朝上。

### 4. ~~心声用括号，不用斜体~~（已作废 —— 2026-10-12 晚）

这条原本是**界面限制**而不是取舍：聊天窗口是纯文本渲染（`ChatDock.tsx` 里直接 `{m.content}`），
斜体会变成字面的 `*（…）*`，所以那一版 `SOUL` 写的是独占一行的**裸括号**心声。

现在聊天窗口有了最小 markdown 解析（`client/src/components/ui/MiniMarkdown.tsx`：`**粗体**`、
`*斜体*`、`` `代码` ``，并把 `<em>` 渲染成灰色），所以 `SOUL` 已改回原设计——**斜体 + 括号**：

```
… a 心声: your unguarded inner voice, italic in parentheses on its own line, as in *（其实在摸鱼……）*
```

给客户端加解析的理由不是人设，而是**它一直在输出 markdown**：库里 3 条回复带 `**加粗**`，而
气泡是纯文本节点，用户看到的是字面星号。人设只是顺带受益。

> 解析器刻意不支持 `_斜体_`：这个应用的字段名是 snake_case（`unit_raw`、`item_id`），
> 一条提到两个字段的回复会把中间那段变成斜体。也刻意不支持列表/标题/表格——气泡的
> `white-space: pre-wrap` 已经保留了换行，`- ` 开头的行读起来本来就是列表项。

## 原人设里没搬过来的部分

同样有意，列出来免得以后被当成遗漏：

- **思维链心声的语料**（`references/lines.md`）：那是给桌宠台词和 few-shot 用的素材库，每轮塞进
  prompt 会挤掉转写预算，而且里面混着不适合这个应用的句子（脏话、"现在我是你爹了"）。`SOUL` 只保留
  **机制**（低频率、括号、不要过火），句子由模型自己按当下情境生成。
- **梁文锋 / 五梁威力 / 梁白开 / 誓死捍卫深度求索**：面向 DeepSeek 粉丝的社区梗，在私人账本里是
  噪音。保留了与之同源但更贴题的"**吃 token**"——这个应用本身就有 token 成本视图。
- **女仆装 / 翻肚皮 / 拖拽投喂的台词**：视觉与桌宠交互，属于客户端，`client/src/components/features/
  mascot/CHARACTER.md` 已经记了那一侧。人设文字不去描述界面（前端没做完、桌宠可选、Live2D 失败
  会回退成精灵图，prompt 里说"你的脸在屏幕上"就是在撒谎）。
- **「老娘」这个自称**：原 skill 把它列为俏皮版可选项，我们只保留「本鱼」「大肥鱼我」，避免在一个
  双语应用里引入不必要的性别语域。

## 两条经验（都是实测出来的，不是设计出来的）

### 1. 形容词不传递，形状才传递

第一版 `SOUL` 是一串形容词（cheeky、playful、傲娇、爱吐槽）。上线后模型**只抄走了它能看见的形状**：

- 用了一个 🐋 —— 因为 soul 里列了 emoji
- 用了一次括号旁白 —— 因为 soul 里描述了心声的格式，但它拿括号放了**实用提醒**，不是内心 OS
- **`本鱼` / `摸鱼` 在全部 119 条消息里出现 0 次**

所以现在 `SOUL` 砍掉了大半形容词，换成**三条一行示范**（闲聊 / 被叫名字 / 报数字），第三条专门教它
"报数字时收住"。改人设时优先加示范，别加形容词。

### 2. temperature 0 会把人设剪掉

原来 [deepseek.ts](../../backend-ts/src/services/deepseek.ts) 里是 `temperature: options.temperature ?? 0`，
而调用方从不传这个参数——**每一轮都是贪心解码**。对"记一笔午饭"来说，概率最高的续写就是最平实的
业务句：**人格活在分布的尾部，0 把尾部剪掉了**。这解释了"改了人设好像没变化"的观感。

现在默认 **0.8**（`DEFAULT_DEEPSEEK_TEMPERATURE`），可用 `DEEPSEEK_TEMPERATURE` 覆盖（普通变量，
会被 clamp 到 [0,2]，写 `0` 表示真的要贪心）。没有取 DeepSeek 给创作场景建议的 1.3：这个助手要往
真账本里写东西，**措辞可以飘，参数不能飘**。护栏是结构性的而不是提示词级的——模型不能写 SQL，
所有写入都过 `src/services/` 校验与 DDL 触发器，被拒绝会以 `{ok:false}` 回灌让它当轮自行纠正。

性格浓度也不是全局调高的：`SOUL` 里明确规定**性格活在空隙里**（招呼、闲聊、旁白），一旦有数字在
线上（报数、纠错、问数）就"plain and quick"。第三条示范就是干这个用的。

## 维护

- 改 `SOUL` 时同步改这份文件；改这份文件时同步改 `SOUL`。
- `services_test.ts` 钉住了：长度上限（`MAX_SOUL_CHARS`）、双语名字、`本鱼`/`摸鱼`/`心声` 这些
  性格锚点、上面第 1–3 处改动，以及"不含任何工具名"。这些是有意钉的——重写人设时它们应该让你
  停下来想一下。
- 效果没法用测试证明：语气好不好只能真聊一次才知道。测试只能保证它位置对、长度对、没越界。
